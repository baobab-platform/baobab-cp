# DEV-06 native owner fixture

The separately built development bootstrap binary exposes only the finite external
capability phases register/activate/unentitled/regrant/absent/restore/retire/read. It requires a marked
disposable development database, live run lease, independent external assignment,
zero estates and distinct existing synthetic maker/checker Principals. No caller
can select a tenant, provider, subscription or binding identifier.

Register validates original pinned Shared engine registration/catalogue, starts
the provider DRAFT and stores immutable owner source/declaration/OCI-manifest
proof. Registration creates no grant or ACTIVE provider. Infrastructure must
construct/verify that real local OCI manifest from the actual built image's config
and layers; an image CONFIG digest is never represented as a manifest digest.
The image is published only to the run-owned private OCI artifact endpoint,
whose original manifest CP fetches and hashes before release admission. No
public/GHCR publication or certification is claimed.

Activate requires a fresh TLS-verified Pulse readiness response reporting both
PostgreSQL and semantic retrieval healthy. It records that actual active probe,
then uses ordinary release-approval and provider-activation changeset plan,
different checker approval and apply. Any normal plan blocker aborts; no status
shortcut or certification record is inserted. Nonproduction release policy
remains its original policy. The synthetic governed actors do not establish a
human appointment, independent legal fact, protected approval or provider certificate.

The external TRIAL source ProductSubscription is produced in CP, references only
this run, expires with its lease and is expanded by the normal ProductVersion/
Composition service into an actual MATERIALIZED subscription-backed grant. The
normal binding repository admits the provider/instance/contract/scope. Neither
Infrastructure nor Pulse writes canonical CP tables. No INTERNAL classification,
payer, financial terms, site, estate, bank/provider authority or money movement
is created.

Unentitled revokes only the owned grant, retaining its ACTIVE source and binding;
regrant uses normal composition expansion and never resurrects a revoked grant.
Independent current row readbacks distinguish these controls.

Absent actually deletes the exact owned source subscription/projection while
retaining its grant, allowing the current-provenance denial to be observed.
Restore reconstitutes that owned source via normal expansion; retired binding
is a final transition through the normal versioned repository and is not undone.
Owner PG17 tests prove guard/refusal and registration replay/no activation. Only
the real Infrastructure composition can qualify the activation/resource journey.
A failed activation can leave partial run-owned records; abandon/recover the
whole disposable run rather than force a plan past a blocker.

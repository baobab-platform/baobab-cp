# CP Console

The Baobab Control Plane Console is the administrative frontend defined by ADR-BCP-019. It is a Next.js App Router
application that runs as its own container and reaches the Go Control Plane API only from the server. The browser
never calls the Control Plane directly, and never holds a token.

FE-01/02/05 foundations, FE-03's confidential session and BFF, and substantial
CX-01–CX-05 operating interfaces are implemented. These include Organisation
360°, exact-grant directories, context switching, enterprise record tables and
nonproduction-gated export/bulk workbenches. The earlier 9 October FE-00
snapshot is historical rather than a current implementation inventory.
See the [CX-05 maintainer guide](../docs/development/cx05-maintainer-guide.md)
and [current Console programme](../docs/frontend/cp-console-experience-programme.md).

**Production status:** This is deployable code, not a completed live IAM/CP/AWS
certificate. Privileged sessions need a real issuer, encrypted Redis, controlled
CP credentials and current permissions. The governed dataset Console and API
flags default off and are refused in production. No browser token, fake
readiness decision or inherited group administration is permitted.

## Stack

| Concern | Choice |
|---|---|
| Runtime | Node.js 24 LTS (`.node-version`) |
| Framework | Next.js 16 (App Router, `output: "standalone"`), React 19 |
| Language | TypeScript 5.9, strict, with `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` |
| Package manager | pnpm, pinned by the root `package.json` `packageManager` and enabled through corepack |
| Lint | ESLint 9 with `eslint-config-next` (TypeScript 7 and ESLint 10 wait on `typescript-eslint` and `eslint-plugin-react` support) |
| Unit tests | Vitest, Testing Library, jsdom and axe-core |

The repository root is the pnpm workspace (`package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`), with this
directory as its only package. The organisation's foundation gates install and audit Node dependencies at the root.
pnpm holds back newly published versions by its default minimum release age, and the workspace makes no exceptions.

## Design system

`src/components` is the Console's own design system (FE-02, prompt §§52-54). Features import from `@/components`.

| Area | Components |
|---|---|
| Tokens | `src/styles/tokens.css`: colour, the nine semantic status tones, typography, spacing, radius, elevation, focus, motion |
| Actions | `Button` (primary, secondary, danger, ghost; `busy`), `ConfirmDialog` (typed confirmation and audited reason) |
| Forms | `Field` (label, hint and error wired to the control), `TextInput`, `Select`, `Textarea` |
| Feedback | `Alert`, `StatusBadge`, `LoadingState`, `EmptyState`, `ErrorState`, `Dialog` |
| Structure | `PageHeader`, `Table` (captioned, server-sorted), `SideNav`, `Tabs`, `SkipLink` |

Rules the components enforce:

- Status is never colour alone. Every tone has a glyph and text, and features keep their precise domain wording.
- Every token pair meets WCAG 2.2 AA contrast. `tests/unit/tokens.test.ts` computes the ratios.
- Dialogs are native `<dialog>` modals, so the rest of the page is inert, and focus returns to the opener.
- Loading states name what is loading, empty states explain what would fill them, and error states give a next step and
  the Control Plane reference.
- Tables sort, filter and page on the server. A sortable header is a link, and its state is exposed with `aria-sort`.
- Reduced motion is honoured, and layouts reflow at 320 CSS pixels.
- Strings live in `src/lib/i18n/messages.ts`, and nothing concatenates sentences.

Every component test runs axe in jsdom. `/design-system` shows every component and state with illustrative data, and
returns 404 when `CONSOLE_ENVIRONMENT` is `production`.

## Control Plane client

The Console never hand-writes Control Plane API types (ADR-BCP-019 §38).
`src/generated/control-plane/openapi.d.ts` is generated by `scripts/generate-cp-client.mjs` from the Shared
`control-plane/v1` OpenAPI pinned in `contracts.lock.yaml`. It is read from the Control Plane's embedded copy, which Go
tests hold byte-for-byte equal to that commit and complete. Never edit it; after the pin moves, run
`pnpm --filter @baobab-platform/cp-console generate:cp-client` and commit the result. CI runs `check:cp-client` and fails
when the committed file does not match the pin.

`src/server/cp-client` is the only way to call the Control Plane. It is server-only and typed from the generated paths:

- Operations Shared declares but the Control Plane does not serve (`unimplemented.ts`, FE-00 G2) are removed from the
  type, so calling one does not compile. `api.TestConsoleExcludesUnimplementedOperations` keeps the list equal to the
  Control Plane's.
- It sends the session's bearer token and a correlation id, and forwards only `If-Match`, `Idempotency-Key`,
  `X-Causation-ID` and trace context besides. Identity and tenant headers are dropped: the Control Plane derives the
  actor from the token (ADR-BCP-022 §§13-14).
- It never caches, never follows redirects, encodes path parameters, and abandons a request after 10 seconds.
- `expectOk` returns the data or throws a `ControlPlaneError` carrying the problem `code`, whether it is retryable, the
  correlation id to show as a reference, and the key of a safe message in `messages.ts`. Problem `detail` is for server
  logs and is never rendered. A stale `If-Match` (412) tells the user to reload rather than retrying (ADR-BCP-022 §131).

Each BFF operation calls one explicit route. There is no pass-through of arbitrary paths (ADR-BCP-019 §42).

## Configuration

Configuration is read only on the server, by `src/server/env.ts`. It is validated when the server starts
(`src/instrumentation.ts`), and invalid configuration stops the process. Lint forbids `process.env` anywhere else.

| Variable | Required | Meaning |
|---|---|---|
| `CONSOLE_ENVIRONMENT` | yes | `development`, `integration`, `staging` or `production` |
| `CP_API_BASE_URL` | yes | The Control Plane API the server calls. It must be https, except `localhost` in development. |

For confidential OIDC routes, configure the `CP_CONSOLE_AUTH_ENABLED`, issuer, client ID/secret,
callback, introspection URL, TLS Redis host/credentials and 32-byte base64 session key
through the server-only validated auth configuration. Never expose those in a
`NEXT_PUBLIC_` variable. See `src/server/auth/runtime.ts` for exact validation.

The optional governed dataset workbench requires `CX05_DATASET_CONSOLE_ENABLED=true`
and the separately approved CP-side `CX05_DATASET_API_ENABLED=true` with
`CP_CONSOLE_DATASET_KEY_B64`. Both remain **OFF by default and nonproduction-only**.
An enablement flag does not grant `organisation.export`, `organisation.bulk.propose`,
`organisation.bulk.approve` or `organisation.manage` and cannot replace
the IAM session assurance evaluation.

## Develop

```sh
make frontend-install   # corepack enable, then pnpm install --frozen-lockfile at the root
CONSOLE_ENVIRONMENT=development CP_API_BASE_URL=http://localhost:8080 make frontend-dev   # http://localhost:3000
make frontend-typecheck frontend-lint frontend-test frontend-build
make frontend-image     # docker build --file frontend/Dockerfile .
```

The Dev Container installs Node 24 and forwards ports 8080 (Control Plane API) and 3000 (Console).

## Image

`frontend/Dockerfile` builds from the repository root (its build context), and `Dockerfile.dockerignore` limits the
context to the workspace manifests and this directory. It builds with the Node 24 image and runs on distroless
`nodejs24-debian13` as a non-root user.
Both base images are pinned by digest. `GET /healthz` reports liveness only, and the image's `HEALTHCHECK` calls it
through `healthcheck.mjs`, because the runtime image has no shell.

Every response carries baseline security headers (`next.config.ts`), including `frame-ancestors 'none'`. The confidential-client authentication and its same-origin CSRF boundary are
implemented, while CSP and browser-hardening work remains subject to its
separate acceptance gates.

## Diagnosing governed Console operations

`src/server/bff/console-datasets.ts` is the fixed-path, same-origin HTTP
boundary; `src/app/api/workspace/datasets/route.ts` obtains the confidential
server-side session and CSRF proof; `src/features/console/dataset-command-model.ts`
validates the action DTO; the workbench renders an independent reviewer flow.
The backend's authoritative counterpart is `api/console_dataset_handler.go`.
Do not infer caller identity or permission from a browser organisation ID.
See [the complete operation/state and security map](../docs/development/cx05-maintainer-guide.md).

## CI

`.github/workflows/frontend.yml` runs only when `frontend/` or the workspace files change. It installs from the
lockfile, then typechecks, lints, tests, builds, audits dependencies and builds the image.
